# Protocol 1

Transport: SSH exec `python3 <quoted-content-addressed-bridge-path>`. UTF-8 JSON line on stdin, JSON object on stdout. No PTY. Maximum input 65536 bytes; maximum prompt 16000 UTF-8 bytes. Herdr subprocess timeout 20 seconds; phone response timeout 35 seconds.

Request fields:

| Field | Meaning |
|---|---|
| `v` | Integer `1` |
| `op` | `hello`, `sessions`, `agents`, `read`, `prompt`, `key`, `catalog`, `history`, `account` |
| `session` | Required for all agent operations; must exist and be running |
| `target` | Explicit live pane ID for read/prompt/key |
| `identity` | Bridge-issued identity digest from the agent list |
| `id` | Mutation UUID for prompt/key; same ID must never have different payload |
| `text` | Prompt content |
| `key` | One of up/down/left/right/enter/esc/ctrl+c |

Responses: `{"ok":true,"data":{...}}` or `{"ok":false,"error":"..."}`.
Hello returns `protocol` and bridge `version`. Sessions omit server filesystem paths. Agents currently preserve Herdr's JSON fields plus an `identity` digest. Read returns Herdr's result object. Prompt/key success means input was sent, not that an agent task completed.

The identity hashes terminal ID, agent kind and available agent-session metadata. Concurrent replacement can still race with CLI execution; this is documented rather than represented as an atomic guarantee.

Errors never authorize a retry. Reuse the same UUID if implementing explicit recovery; an unfinished receipt reports unknown instead of replaying. The current phone UI uses manual inspection after failures and does not implement automated recovery.

## Read-only transcript extension (bridge 0.3.0)

Protocol stays v1; deployments are content-addressed, so the app always installs its exact bundled adapter version.

- `catalog`: optional `query` (max 200 characters), `offset` (nonnegative integer), `thread` (exact session/thread identifier). Returns `records`, `total`, nullable `next`; pages contain at most 100 metadata records.
- `history`: `record_id` from catalog and optional `before` byte offset. Returns normalized `messages`, `children`, `before`, `has_more`, and bounded/partial indicators. Default reads the latest window; byte cursors keep older pages stable when the file is appended. Each scan window is 2 MB; a page skips sparse/internal tails across up to 16 MB total. Normal rows crossing window boundaries retain complete-line cursors. Each displayed block is capped at 16 KB UTF-8, marked `truncated`.
- Message kinds: `user`, `assistant`, `tool`, `result`; fields include stable byte-offset `id`, `timestamp`, `text`, `title`, `call_id`, `truncated`. Commands/results link by `call_id` when both are present in loaded pages; a result without its call is shown independently.
- `account`: returns `ssh_user` and `hostname` only. Does not read provider accounts, tokens, email addresses or plans.

History does not require a running Herdr session and never accepts a caller-selected filesystem path. A SHA-256 identifier resolves only through the approved transcript roots. A history record is not a terminal target. Only explicit live-agent or ordinary-pane operations can send input, with session/identity checks and mutation receipts. Independent SSH shell input uses its own terminal identity and sequence.

Codex adapters read session_meta and response_item records; Claude adapters read user/assistant message blocks and the documented subagents layout. Private reasoning/system/developer records are omitted. Related upstream references: [Codex rollout reducer](https://github.com/openai/codex/blob/main/codex-rs/rollout-trace/src/reducer/thread.rs), [Claude subagent documentation](https://code.claude.com/docs/en/sub-agents). Local fixture and installed-version verification is required when schemas change.


## Terminal extension (v0.4.0, protocol remains v1)

- `panes(session)`: ordinary panes in all workspaces; includes pane/terminal/tab/workspace IDs and identity. Recognized Agents are excluded.
- `paneRead(session,target,identity)`: validates the live ordinary pane and returns 400 recent-unwrapped lines as plain `text` plus SGR-only `ansi` (cursor moves and all other escapes removed, like the tmux snapshot), so the phone paints the same colours.
- `agents(session)` and `status(session)` accept `panes: true` (the phone's 会话 list while it is on screen): the answer adds `panes`, the same ordinary panes, each with `tab_label` (Herdr's tab label) and, from one read-only `pane process-info` per pane (in parallel), `kind` and `foreground`. `kind` is `shell` (only shells in front), `run`, `ssh` (ssh / mosh), `tmux` (a tmux client), `ch` (ch's relay or SSH attach whose agent Herdr does not list right now) or `herdr` (a Herdr client); `foreground` is the front process name only (≤ 40 characters), never its arguments. A pane whose process info cannot be read has neither field. When listing the panes fails, `panes` is left out and the agents answer stands. Without the flag nothing extra is read. The 会话 list shows these panes as 「Herdr 终端」 except Herdr-listed agents, `ch`, `herdr`, and `tmux` while the tmux section lists panes (that session is listed there).
- `paneRun` / `paneText`: validated destination plus text, UUID receipt; run appends Enter, text does not. Input is bounded to 16000 UTF-8 bytes. `paneKey` and `tmuxSend {action:"key"}` share one key grammar: optional `ctrl+`, `alt+`, `shift+` in that order, then `esc`, `tab`, `enter`, `backspace`, `space`, `up`, `down`, `left`, `right`, `home`, `end`, `insert`, `delete`, `pageup`, `pagedown`, `f1`–`f12`, or one printable ASCII character (`|`, `~`, `;`, `\`…). A combination with no key code (`ctrl+1`, `ctrl+|`) is refused with `没发出去：这个组合键在终端里没有对应的按键码` and nothing is written.
- Herdr: a key whose `pane send-keys` name produces exactly the xterm bytes is sent by name (cursor keys follow the pane's cursor-key mode; F1–F12, Enter, Esc, Tab, Backspace, Space, and their modifiers). Where Herdr differs (no Home/End/PgUp/PgDn/Insert/Delete; plain Tab for Ctrl+Tab; `?` for Ctrl+?; modified F3; Ctrl+Alt+Shift+Backspace) the xterm bytes go as `pane send-text`. NUL (Ctrl+Space, Ctrl+@) is only ever sent as `ctrl+space` / `ctrl+alt+space`. tmux uses its `send-keys` names (`S-Left`, `C-Left`, `M-x`, `F5`, `PPage`, `NPage`, `BTab`, `IC`, `DC`…); where a name would be wrong (Shift/Ctrl+Enter, Alt+Shift+Tab, unknown names tmux would type as text) the bytes go as `-l --`, and a trailing `;` is escaped.
- `paneRead` accepts an optional `revision` (the Herdr pane revision the phone last read): an unchanged pane answers `{same:true,revision}` without the 400-line read, and a read result carries `revision`. `tmuxRead` accepts an optional `known` (the 16-hex hash of the coloured screen the phone has): the same screen answers `{same:true,known}`. The phone polls 180–250 ms right after input and while output changes, then backs off to 2 s when idle; only changed lines are repainted.
- The independently opened SSH PTY does not use the Python bridge. Native `shellOpen` allocates an opaque terminal ID. Read uses an absolute byte cursor over a 1 MiB ring, returns base64 bytes, next cursor, lost/ended/error; `wait:true` arms a one-shot native wake when nothing is new, so output reaches xterm without polling, with a slow fallback read. Native writes carry terminal ID and strictly increasing sequence. The sequence is consumed before socket write; unknown outcomes freeze the UI input stream. No auto retry, reconnect, or replay. Resize is clamped to 20–400 columns and 5–200 rows; close only closes the explicitly opened channel.
- No terminal bytes or typed commands are persisted by the app. The remote shell may maintain its own shell history. Real-server checks stay read-only; mutation tests use isolated CI fixtures.

## Live tmux attach (protocol remains v1)

- Native `shellOpen {attach: {target, identity, readOnly?}}` opens an exec channel on the same SSH session running `python3 <bridge> --tmux-attach <pane> <identity> [--read-only]` with a PTY. The bridge re-lists that pane on its live server (default or named by socket) and requires the same identity; otherwise it prints `没连上：…` and exits 2 without starting a client. It then replaces itself with `tmux -u [-S <socket>] attach-session [-r] -t <session-id>`, with `TMUX` / `TMUX_PANE` removed from the environment.
- Output and keys then use the ordinary PTY ops above (cursor, `wait`/wake, sequence, resize); no bridge request, receipt or transcript is involved. `-r` is a tmux read-only client (tmux discards input; the phone also refuses to write). A read-write client follows the session's current window, which may differ from the tapped pane. Closing the channel detaches the client; the session and its programs keep running.


## History association and remote routing (v0.4.0)

`agents` adds `history_ref` without changing the original agent identity digest. A `matched` reference has `record_id`, `thread`, and `source` (`herdr`, `process`, or `ch-route`); remote matches also include `record` and `remote`. Herdr transcript-path references must already exist in the allow-listed catalog. Native process `resume` / `--resume` UUIDs and open transcript FD links are exact evidence. Duplicate rollout copies with the same provider/thread select the most recently modified copy. Generic project cwd or recency never authorizes automatic matching.

Unresolved references explicitly report `unavailable`, `missing`, `ambiguous`, `remote`, `remote_candidates`, `remote_missing`, or `remote_error`, with optional `reason`, `query`, and up to 12 inline metadata `candidates`. These are suggestions for explicit selection, not send destinations. Manual association retains the existing pane/identity and requires the app's explicit confirmation.

`transient: true` marks a reference that decided nothing because something could not be read this time: `retry` (Herdr's process lookup failed), or `remote_error` (the other computer did not answer, the read hit its time limit, or ch's relay is between two SSH connections). The app keeps what it shows and retries; `remote_missing` / `remote_candidates` mean the other computer answered and there really is no verifiable id.

Remembered links (`~/.local/state/herdr-pocket/links-v1.json`, 0600, record metadata only, ≤ 300 entries, 60 days) are kept per pane run: Herdr session + pane + terminal + agent kind, checked against the run mark (pid and start time of the native agent, or of the ch relay, which outlives reconnects). A different run drops the entry. `auto` is the last conversation the evidence confirmed: while a reference is `transient` the bridge returns that record instead, as `matched` with `stale: true, transient: true` and the reason. `manual` is set by `link`; it is returned as `matched` with `source: "manual"` (and `auto_status`) whenever the evidence does not name a conversation itself, and it ends when native-process, title or open-file evidence names one, or when the run changes. Remote records are only reused on the same route, with the pane's current `remote` context.

- `link(session, target, identity, record_id)` stores a manual pick for that live agent; `clear: true` removes it. The record must be a root record of the computer that holds the pane's history: a local catalog record for a local pane; for a ch pane, `remote:<route key>:<hash>` of that pane's route, re-listed through the remote `catalog` read (never metadata sent by the phone). Returns `{linked: <matched ref>|null}`. It writes nothing but the links file.
- Herdr 0.8.2 lists a ch pane as `agent: "ch"` with `display_agent: "claude"` (or `"codex"`). History resolution, catalog/history reads, `glance` and sub-agent reports use `display_agent` as the conversation provider; identity, prompts, keys and answers still address the ch pane itself. The relay fallback that sends pane-level input is decided by probing as `display_agent`, never as `ch` (the ch executable would otherwise look like a native agent in the pane).

History resolution uses the strongest available evidence, and a weaker source never overrides a stronger one:

1. **native-process** — the live Claude process holds its runtime directory `/tmp/claude-<uid>/<project>/<session-id>/tasks` open; the session ID in that FD link is the conversation currently on screen (it follows `/clear` and `/resume`).
2. **title** — the Codex TUI sets the terminal title to `<thread name> | <cwd name>`. It is matched against `~/.codex/session_index.jsonl` names, preferring threads the Codex app-server has loaded (`~/.codex/thread-writer-locks/<id>.lock`). Duplicate names are only accepted when exactly one is loaded.
3. **open-file** — a transcript JSONL the native process holds open.
4. **herdr** — Herdr's reported `agent_session` (can be stale after switching sessions inside the TUI).
5. **process** — `--resume`/`resume` IDs in argv (startup only; stale after an in-app switch).

For a live ch-cli SSH attach, process argv identifies the established SSH destination and route workspace. ch's relay (the pane's foreground process) names the same route in its own argv (its attach and reconnect commands as JSON items); that route is used for history while the relay reconnects (no ssh child for a few seconds after a network drop), reported as transient `remote_error` without a read, never as a local lookup. Input still requires the live attach. One SSH round trip per remote account (all accounts in parallel) runs op `resolve`, which applies rule 1 inside ch's tmux pane and opens only the matching transcript. When no live ID is found, the candidates are the root conversations in that route's own Claude project directory; they are never selected by newest timestamp. ch starts a moved conversation as `claude --resume ~/.local/share/ch/transfers/<id>/<session>.jsonl --fork-session`, and Claude writes the fork's own transcript only with the first new turn: when the one native process in the route's pane was started on such a transfer copy, has no live session id, and the route's project directory has no transcript yet, that copy is the match (`source: "ch-transfer"`); otherwise it is one more candidate. The remote `catalog` read (the picker) lists the project directory plus that copy. The copy's path never leaves the other computer.

Remote records have IDs `remote:<route digest>:<opaque record hash>` and a `remote` context containing Herdr `session`, `target`, `identity`, and provider. `catalog` and `history` accept that context; each request revalidates the live pane and rediscovers its SSH route. A stale route or mismatched namespace fails explicitly. Children and parent navigation preserve remote context. Catalog query/offset/thread semantics remain the same; local catalog remains available without a live Herdr session, while remote routes require their live attach pane.

Remote reads execute only allow-listed resolve/catalog/history/image reads, through one fixed loader command: `ssh -T -o BatchMode=yes -o StrictHostKeyChecking=yes -o ClearAllForwardings=yes -o ConnectTimeout=8 -o ServerAliveInterval=10 -o ServerAliveCountMax=3 -o ControlMaster=auto -o ControlPath=~/.herdr-pocket/ssh/cm-%C -o ControlPersist=300 <route args without -S> python3 -I -c '<loader>' <adapter sha256>`. stdin is `<n>\n`, n adapter bytes (0 = use the stored copy), then the JSON request line. The loader runs `~/.herdr-pocket/bridge/<sha256>.py` of the remote user only when it is a regular, user-owned, non-writable-by-others file whose bytes hash to that SHA-256; otherwise it answers `{"helper_missing":true}` and the bridge resends with the adapter on stdin, which is hash-checked, run and stored atomically (0700/0600, newest 3 kept). An unsafe or over-long control folder falls back to `ControlMaster=no -o ControlPath=none`; a timeout tears the shared connection down, and an ssh failure (exit 255) is retried once without sharing. No remote cache of history data is written. Measured over a 275 ms link: ~1 s per warm read, ~4.5 s for the first read after 5 idle minutes (new SSH login). One remote host index (including failures) is reused within a bridge request. Each SSH read has at most 15 seconds; agent enrichment has a 22-second aggregate remote budget. Remote output is capped at 2 MB and oversized/error responses are reported, never converted into an empty history. The UI keeps errors visible with an explicit retry button.


## Pictures (protocol remains v1)

- **Phone**: pictures come from the system photo picker (or `ACTION_GET_CONTENT` before it exists) or the camera app writing into a private, non-exported provider; no storage or camera permission. Each picture is rotated upright, scaled to a 2048 px long edge and re-encoded (PNG kept when small, otherwise JPEG ≤ 1.3 MB), which drops EXIF including location. Bytes stay native; the WebView gets a 360 px preview and an opaque id.
- **Upload** (native SFTP, not a bridge op): `~/.herdr-pocket/uploads/<UTC day>/<sha256>.<jpg|png>` plus `<sha256>.thumb.jpg`; folders 0700, files 0600, written to a temp name and renamed. Content-addressed, so a retry finds or rewrites the same file. Uploading never touches an agent.
- `prompt` accepts `images`: one or more `{name: "<day>/<sha256>.<ext>", sha256}` (no count cap; the 65536-byte request bounds the list) and an optional `remote` hint; `text` may then be empty (≤ 15000 bytes). Before the receipt is written the bridge checks each name, that it is a regular non-symlinked file of this user, and its SHA-256, then probes the pane: a local pane gets `[图片] <absolute path>` lines after the text; a ch-cli route runs `ch share-image <path>` (it only caches the file and prints `ch-file://<sha256>.<ext>`, which must match the hash) and gets `[图片 · ch-local fetch] <address> （用 ch-local fetch 取回再看）` lines (the note keeps the line from ending in a picture name: Claude Code checks every pasted line that does as a picture path and, for one that is no local file, reads the clipboard first, see «The agent's input box»; the phone hides the whole line, and older lines without the note render the same); a pane that SSHes elsewhere without a ch route is refused. All of these refusals start with `没发出去` and leave no receipt. The result adds the final `text`. For a Claude Code or Codex agent the bridge first reads the coloured visible screen; text already in the agent's own input box is replaced by this message, never joined to it (see «The agent's input box» below). An empty box's placeholder or suggestion is told apart by being drawn dim/grey; when the screen cannot be read, has no colours or shows no input box, the prompt goes as before. A question or approval dialog on screen with no input box refuses the prompt (and `exitAgent`) too (`没发出去：它正停在一个提问或选择框上…`, no receipt): Herdr 0.8.2 misses Claude's dialog in a narrow pane, where its footer wraps, and reports the agent idle/done, while typed text plus Enter would pick or tick an option. Day folders older than 14 days are pruned opportunistically.
- `image`: `variant` `thumb`/`full`; `kind` `upload` (`name`), `ch` (`address`; our upload with that hash first, else `~/.local/share/ch/attachments/<sha256>.<ext>`), or `transcript` (`record_id`, message `item` id, content `block`, optional `remote` context; reads that one line back and decodes the embedded Claude base64 / Codex data-URL picture). Never a caller-chosen path. Returns `{mime, data(base64), bytes}`; at most 1.35 MB, shrunk with Pillow when installed, otherwise refused. The phone re-encodes it to ≤ 360/1600 px before the WebView sees it.
- `history` user messages carry `images: [{block}]` for pictures embedded in the transcript; the placeholder text and Codex `<image>` wrappers are dropped.

## Files (protocol remains v1)

- **Phone**: any file from the system document picker (`ACTION_OPEN_DOCUMENT`, multi-select, no storage permission); at most 4 per message and 25 MB each. The name is sanitized on the phone (NFC; `/` and `\` become `_`; control, format/bidi, line-separator and private-use characters dropped; no leading dot or space; ≤ 120 UTF-8 bytes keeping the extension). Only an id, the name and the size reach the WebView.
- **Upload** (native SFTP, not a bridge op): the content URI is streamed and hashed on the way into `~/.herdr-pocket/uploads/<UTC day>/.<random>.part`, then moved to `<UTC day>/<first 16 hex of sha256>/<name>` (folders 0700, file 0600). The same content and name land on the same path, so a retry is harmless. Then `fileCheck {name, sha256}` re-hashes it on the computer; a wrong copy is deleted (`{match:false}`) and uploaded once more.
- `stageFile {session, target, identity, name, sha256, remote?}`: run by the phone for every file before the prompt; never sends input to an agent. It re-hashes the upload and probes the pane: a local pane returns `{remote:false, path}`; a ch-cli route copies the file to the other computer (below) and returns `{remote:true, path}`; any other SSH pane is refused with `没发出去：…`.
- **Remote copy**: `ssh -T -o BatchMode=yes -o StrictHostKeyChecking=yes -o ControlMaster=no -o ControlPath=none -o ClearAllForwardings=yes -o ConnectTimeout=8 <route args without -S> python3 -c '…'`, with the bundled adapter and then the file's bytes on stdin (≤ 25 s). It writes only `~/.herdr-pocket/uploads/<day>/<prefix>/<name>` of that SSH user (umask 077, real non-symlinked folders owned by the user, `O_EXCL|O_NOFOLLOW` temp file), checks size and SHA-256, and links it into place without ever replacing a different file. Remote day folders older than 14 days are pruned the same way.
- `prompt` accepts `files`: 1–4 `{name: "<day>/<prefix>/<name>", sha256}` (with or without `images`; `text` may then be empty). Before the receipt the bridge re-hashes each file; a local pane gets `[文件] <absolute path>` lines after any `[图片]` lines; a ch route first checks over the same SSH route that every staged copy exists with that hash, then gets `[文件] <remote absolute path>` lines. Every refusal starts with `没发出去` and leaves no receipt.
- `fileInfo {names: [≤ 60 relative names]}` → `{files: {name: {size} | {gone: true}}}` for history chips (invalid names are skipped). The phone shows history lines `[文件] …/.herdr-pocket/uploads/<day>/<prefix>/<name>` as chips; tapping one offers to copy the path or the name. Nothing is downloaded back to the phone.

## New sessions (protocol remains v1)

- `createInfo(session)`: read-only. Installed kinds (`codex`, `claude`, `ch`; looked up on PATH and common user bin folders), workspaces with the shell directories their panes use, and suggested directories (pane directories first, then up to 12 recent history directories that still exist; temp and hidden folders are skipped).
- `create(session, id, kind, cwd, workspace)`: no other fields are accepted. `kind` is one of the three above; `workspace` is an existing workspace ID (new tab there) or `new` (new workspace). `cwd` (absolute, `~`, `~/…`, or relative to `$HOME`; no `~user`, no `..`) may be any existing directory the SSH user can enter (`os.access` X_OK), inside `$HOME` or not, hidden or not, named directly or through a symlink; it is resolved to its real path, which is what Herdr is given. A missing path (`没创建：目录 … 不存在`), a dangling link, a non-directory or a directory without search permission is refused. All of this is checked, and the executable must be found, before the UUID receipt is written; these refusals start with `没创建`, and so do failed reads before the receipt (session offline, Herdr not answering the workspace list).
- `dirList {path | paths, hidden?, query?}`: read-only, no session needed (works the same on tmux-only computers and behind jump hosts). The 新建 sheets' 「浏览目录…」 tree reads one level per tap with it. `path` is absolute, `~` or `~/…` (no `~user`, no `..`; only text work before the read); `paths` (1–16) reads the way down to a start directory in one round trip and answers `{lists: [listing…]}`. A listing is `{path, real?, parent?, home, enter, list, write, dirs, total, truncated, hidden, skipped, partial, note?}` or, for a directory that cannot be read, `{path, home, error, code, dirs: []}` with `code` `missing`, `notdir`, `denied` (with `enter`/`list`/`write` when known), `timeout`, `budget`, `bad` or `os`. `dirs` holds folder names only, sorted case-insensitively, at most 500 (`truncated` when there are more, or past 20000 directory entries looked at): `{name, link?, real?, enter?: false, list?: false, write?: false, slow?: true}`. Entries are classified with `lstat` semantics (d_type, never following a link); a symlink is listed only when `stat` says it leads to a directory, with its target text as `link` and its real path as `real`. Hidden folders (leading `.`) are left out unless `hidden: true` (`hidden` counts them); names that are not valid UTF-8 or hold control / bidi characters are skipped (`skipped`). `query` (≤ 100 characters) keeps names containing it, case-insensitively, so a folder past the first 500 can still be found. Each directory is read in a forked child with stdout/stderr on /dev/null and a 4 s deadline (9 s per request): a hung mount answers `timeout`, and links whose targets did not answer in time are returned as `slow` with `partial: true`. No file names, sizes, times or contents are ever returned.
- Herdr primitives only, never focusing the new tab: `tab create --workspace <id> --cwd <dir> --no-focus` or `workspace create --cwd <dir> --no-focus`, then `agent start pocket-<id prefix> --kind <codex|claude> --pane <new pane> --timeout 3100` (no agent arguments), or for `ch` the fixed text `ch new` via `pane run` into the brand-new shell pane, followed by about 3 s of `pane get` looks for a Claude there. The short wait is deliberate: Herdr 0.8 needs a timeout above 3000 ms, and when it runs out the agent keeps starting in the pane (checked with Herdr 0.8.2), so the request answers in about 4 s instead of waiting for the whole startup; the phone polls the rest. A shell that is not at its prompt yet (`agent_pane_busy` in Herdr 0.8.2, `agent_pane_unavailable` before; nothing typed) is retried for up to 8 s, then reported as `failed` with `typed: false`. A Herdr that refuses the timeout value (`invalid_agent_timeout`, nothing typed) gets one retry with 20000 ms. Everything stays within a 26 s cap.
- Result: `{created, kind, cwd, pane_id, tab_id, workspace_id, new_workspace, state}` with `state` `ready`, `blocked` (startup question, e.g. folder trust), `starting` (not visible yet / timed out; may still come up) or `failed` (`code`, `detail`, `typed`). The receipt is saved as soon as the tab exists, so a retry with the same ID reports that pane instead of creating another; an unfinished receipt reports unknown. A tab whose agent failed is left open, never closed automatically.
- `create` with `kind: "shell"` (会话 「新建终端」, not offered by `createInfo`): only the tab (or workspace) is created, nothing is started or typed; `resume` is refused. Same receipt (saved once the tab exists, before anything else). Result has `state: "ready"` and, when a read-only `pane get` finds the new pane without an agent, `pane` (the pane with its `identity` and `workspace_label`) so the phone opens its terminal at once.
- `starting` without `detected`: the phone closes the sheet at once and shows a 「正在启动」 row at the top of 会话 (per computer and Herdr session). It polls the read-only `status` every 1.5 s until Herdr lists an agent in that pane, then opens its chat (or, when something else is on screen, says so and keeps the first message as that agent's draft). After 45 s the row says it is taking long; after 2 minutes it stops asking and stays until dismissed (「不等了」, which only forgets the row). Nothing is ever started again from there; an unknown `create` outcome still says to refresh first.
- The optional first message is not part of `create`: the app sends it afterwards with a normal `prompt` (its own receipt) only when the new agent is listed as idle; otherwise it stays in the input box.

## Resuming a conversation (protocol remains v1)

- `create` accepts `resume` and `workspace: "auto"`. `resume` is `{id}` for `kind` `claude` / `codex` and `{id, host}` for `ch`; other kinds and keys are refused. `id` is a lowercase UUID: the transcript's own session id (Claude) / thread id (Codex, `session_meta.payload.id`) or the ch session uuid. It must be a root record of the local catalog for that provider (`没继续：这台电脑上没找到这段对话的记录…` / `…这是子 Agent 的记录…`); a ch `host` must be a `[hosts.<name>]` of ch's config (`~/.config/ch/config.toml`, or `$XDG_CONFIG_HOME/ch/`).
- Order: shape checks → receipt peek (a known id answers its stored result) → executable (`没继续：这台电脑上没找到 codex 命令（装好，或检查它在不在 PATH / ~/.local/bin 里）`) → Herdr workspaces → `cwd` (`没继续：目录 … 不存在了（可能被删掉或改名了）`) → record → running check → receipt. Every refusal before the receipt starts with `没继续：`, including an offline session.
- Running check: a process of the SSH user whose Claude runtime task folder (FD link, follows `/clear` and `/resume`) is that id, or without one whose argv has `--resume` / `-r` / `--session-id` with it; a Codex process with `resume <id>` (not `app-server`, `exec`, …); for ch an SSH attach whose route workspace is that session. Refusal: `没继续：这段对话已经在运行了（在某个终端里开着）。打开那个就行，不用再开一个`.
- Start: Claude `herdr agent start <name> --kind claude --pane <p> --timeout 3100 -- --resume <id>`, Codex `… --kind codex … -- resume <id>` (verified live with Herdr 0.8.2, Claude Code 2.1.268, codex-cli 0.163.0: both CLIs print exactly these lines on exit; the resumed transcript is appended to the same file), ch: `pane run <p> "ch --host <host> resume <id>"` then the usual ch look (the same command ch's own relay keeps for reconnecting). Everything after the tab is the `create` flow above (`starting` → 「正在启动」 row, receipts).
- `workspace: "auto"`: the workspace whose panes sit in the real `cwd` (most agents, then panes), else a new workspace; the result adds `workspace_label`. Result adds `resume: {id[, host]}`.
- `tmuxNew` accepts `resume: {kind, id[, host]}` with the same checks; after `new-session` (and once its pane runs a shell) the line `claude --resume <id>` / `codex resume <id>` / `ch --host <h> resume <id>` is typed with `send-keys -l --` and `send-keys Enter` into that pane only. Result adds `resume` and `typed` (false with `detail` when the pane was not found or tmux refused; never typed again).
- `agents` adds `ch_resume: {host, session}` for a ch relay pane: read from the relay process's own argv item `["ch","--host",<host>,"resume",<uuid>]` (data only) and kept only when its uuid equals the live SSH route's workspace.
- Phone (pickup.js): 「继续这个对话」 in 历史 row actions, the read-only view's footer and ⋯, and an exited agent's card; 「打开在线会话」 instead when a listed agent (Herdr or tmux) shows that conversation. 「最近断开的」 on 会话 lists conversations seen running here in the last 3 days that are no longer listed and whose pane is gone (Herdr `panes` read once per new candidate: same pane id + terminal id still there means the agent was quit, not listed; tmux: same pane id + pane identity). 「全部继续」 confirms with a checklist and sends one `create` at a time; those rows do not open chats by themselves. Herdr is used whenever a session runs; `tmuxNew` only on a computer without Herdr. `window.pickupAll()` / `window.pickupCount()` are there for other screens (the Herdr guardian).

## Closing sessions (protocol remains v1)

- `closeInfo(session, target, identity)`: read-only. Re-checks that the pane still holds what the phone showed (the agent's identity, or for a plain shell pane `identity(pane)`), then returns `{pane_id, agent, agent_status, focused, workspace_label, tab_label, tab_panes, workspace_panes, exit_command, ch, ch_session}`. `ch` is true when the pane's process tree is a live ch-cli SSH attach.
- `exitAgent(session, target, identity, id)`: a normal receipt-backed mutation (same path as `prompt`; no other fields). Only for an `idle`/`done` agent; the bridge picks the text itself — Claude Code `/exit`, Codex `/quit` — and submits it with `agent prompt`. Herdr's not-sent refusals come back as `没发出去：…`. The pane stays a shell. Result adds `command`.
- `closePane(session, target, identity, id)`: no other fields. The receipt is written first; then the live pane is re-checked (refusals are stored as `{closed:false, refused}` and reported as `没关：…`), and only `herdr pane close <target>` runs. A Herdr refusal is `没关：…` (stored as `{closed:false, code}`); a timeout leaves the receipt open and reports `关闭结果未知：…` (the same id then never runs again). Result `{closed:true, pane_id, agent, verified}`, `verified` when a follow-up `pane get` says `pane_not_found`. The phone never retries either op on its own; every tap uses a fresh id.
- ch-cli panes: the local pane only runs the SSH attach to a tmux session on the other computer (`destroy-unattached off`, `remain-on-exit off`). Closing the local pane detaches and leaves that session running (`ch resume`); exiting the agent ends the remote session and the local attach returns to its shell.
- `hidden(add?, remove?)`: history records hidden in the app. Only record IDs (64 hex, or `remote:<24 hex>:<64 hex>`, ≤ 200 per call, ≤ 2000 kept) in `~/.local/state/herdr-pocket/hidden-records.json` (0600). Transcripts are never touched; the app filters its list and shows them under 「已隐藏」.

## Dialogs Herdr does not see (protocol remains v1)

- Herdr 0.8.2 misses a Claude question / approval dialog when a narrow pane wraps its footer ("Esc to" / "cancel") and reports the agent `idle`/`done`. `agents`, `status`, `read` and the agent mutations therefore look at the visible screen of each idle/done Claude / Codex agent (one `agent read --source visible --format ansi` each, in parallel): when its input box is not on screen and a dialog that waits for the person parses there, the row says `agent_status: "blocked"`, `screen: "menu"`, `herdr_status: <what Herdr said>`. The identity digest is unchanged. Such a dialog is an approval (permission, folder trust, Codex approval), the answer review, a Claude question (tabs, a text row, a "Chat about this" row or checkboxes), or a **picker** (below).
- **Pickers**: a plain single-choice list drawn in place of the input box, with a key hint under it ("enter select · esc back", "Press enter to confirm or esc to cancel", "Enter to confirm · Esc to exit"), no text row, checkboxes or tabs, and not a Codex request_user_input question ("submit answer", "unanswered", "add notes"). Seen live: Codex 0.163 near its weekly limit puts up "Approaching rate limits / Switch to gpt-6-luna for lower credit usage?" (1. Switch… 2. Keep current model 3. Keep current model (never show again)) right after a turn, and Herdr calls it `done`. A /model (or /resume…) the person opened looks the same on screen and is treated the same: either way no message can go in until it is closed, so the phone shows a card and holds the queue instead of 「已完成」. Such a row (Herdr `status` / `agents`, tmux rows) and its `read` add `picker: true`; `menu.picker` is true, and `menu.question` is the picker's title in front of its question ("Approaching rate limits — Switch to gpt-6-luna for lower credit usage?"). `menu.esc.action` is `back` for "esc back" (Esc closes the picker, nothing chosen). Only Claude / Codex menus are pickers.
- A prompt or key that went in, and a prompt refused because a dialog is where the box was, drop that terminal's "box settled" note (below), so the next status reads its screen once more and reports the picker even when Herdr's state did not change (seen live: "/model" sent from the phone leaves Codex 0.163 `idle` in Herdr; a /model opened on the computer long after the last turn).
- So the phone shows the answer card, keeps queued messages waiting, refuses Shift+Tab, and `answer` drives the dialog with the usual checks (fingerprint, one key at a time with a re-read, Enter only on a verified row). A prompt is refused with `没发出去：它正停在一个提问或选择框上…`, which the queue retries by itself once the dialog is gone. On a picker the card is titled 「Codex 等你选择」 (「/model · 选一项」 when the phone's own command card opened that picker), its button is 「就选这个」, the chat state reads 「等你选择」 and queued messages 「选完再发」; Esc is offered as 「关掉选择框」 (nothing chosen).
- Cheap: an agent whose input box was on screen at least 3 s after Herdr's last state change for it (`state_change_seq` + status) is not read again until that changes. The note (`terminal_id` → that mark and two timestamps; no screen content) is `screens-v1.json` in the state folder; gone terminals are dropped.
- Claude's folder-trust dialog has unnumbered rows ("❯ No, exit" / "Yes, I trust this folder"). It is parsed as an `approval` only when it is exactly that (two rows, a "No…" and a "Yes…trust…", the trust question above); its `esc.option` is the "No, exit" row, since Esc there makes Claude quit. It is answered only by an explicit `answer`, never automatically.
- `menu.esc` reads the hint rows below the dialog as one text, so a wrapped "Esc to" / "cancel" still counts.

## Agents in tmux panes (protocol remains v1)

`tmux` lists the panes of every tmux server of the SSH user: the default one and named ones (`tmux -L name`) found as sockets in the user's tmux socket directories (see SECURITY.md). Result: `{available, panes, looked, skipped, servers}`. A pane of a named server has `pane_id` `%N@<12 hex>` (its server's key; default-server panes keep plain `%N`) and `server` (the socket name); every op that takes a pane id (`tmuxRead`, `tmuxSend`, `tmuxKill`, the agent ops below) reaches exactly that server with `-S <socket>`. `tmuxNew` always creates on the default server and `tmuxInfo.sessions` names only default-server sessions. `looked` = the socket directories read (the default one even when missing), `skipped` = up to 8 `{path, reason}` that were refused (not owned by the user, group/world-writable, symlink), `servers` = `{name, default, state: running|none|error, panes[, error]}` per server.

A Claude Code / Codex process found in a tmux pane of the SSH user (`tmux` op, `agent` on a pane) is addressed by `target` = tmux pane id (`%N`, or `%N@<key>` on a named server) and the agent `identity` (pane identity + agent pid + start time). The agent ops then run on tmux instead of Herdr, with the same receipts and refusal wording:

- `read`: `{text, agent_status, modes, bg[, ansi][, menu][, picker]}`. The state comes from the screen: `blocked` when a numbered menu parses, `working` when the footer offers "esc to interrupt", else `idle`. `menu` (parse_menu) is attached while blocked, or with `menu: true`; `picker: true` (also on the pane's row) while blocked on a picker (see «Dialogs Herdr does not see»).
- `status` with a target: `{tmux: true, agents: [row]}` (one process walk and one screen read; empty when the pane or its agent is gone). `status` with `tmux: true` and no target: Herdr's status rows when `session` is named and Herdr exists, followed by every tmux agent row (the background watcher).
- `prompt`: only while the screen reads idle, or while a Claude Code agent is blocked inside a foreground `Agent` / `Task` call (Herdr still says `working`; the newest row of its own transcript is that tool_use with no result, and its coloured input box is on screen). In the latter case the message is typed and submitted as usual and Claude Code queues it for after the current turn; it is still addressed to the parent pane, never to a sub-agent. Everything else is refused (`Agent is busy or waiting for confirmation…` / `没发出去：Agent 正停在…`; the phone queues). Codex reads idle only with its own composer and footer on screen. `images` / `files` name the phone's uploads, re-hashed before the receipt; the pane is local, so the prompt gets `[图片] <path>` / `[文件] <path>` lines. With the box on screen in colour (the normal case, `capture-pane -e`) the message replaces what is in it and goes in as one `paste-buffer -p` with a checked Enter (see «The agent's input box»), keys `C-e C-u C-k BSpace`; captured without colours, a non-empty box is refused (`没发出去：它的输入框里有字，可…看不清…`) and an empty one gets the old paste / `send-keys -l` plus Enter after 0.3 s.
- `stageFile`: re-hashes the upload and returns `{remote: false, path}`.
- `answer`: same request as for Herdr. The receipt is written before the first key; keys are `tmux send-keys Up|Down|Enter`, the text row gets `send-keys -l -- <text>`, and the screen is re-read after every key (`capture-pane`), stopping before Enter on any doubt.
- `key`: the agent key list; `shift+tab` is sent as `BTab` only while the agent's input footer is on screen and no menu waits.
- `exitAgent` is refused (close the pane with `tmuxKill`).

## The agent's input box (protocol remains v1)

A `prompt` to a Claude Code / Codex agent whose input box is on screen (Herdr: `pane read --source visible --format ansi`; tmux: `capture-pane -p -e -J`) replaces whatever is in that box and only reports it sent once the box has emptied again. Same for direct sends, the queue and 立即发送 (they are all `prompt`), for Herdr panes, ch relay panes and tmux panes. Herdr panes use pane-level input for this (`pane send-keys`, `pane send-text`), which is the same for a local agent and a ch relay pane.

- **Why**: seen live with Claude Code 2.1.268: a paste whose text ends in a picture name that is not a local file (the ch route's `[图片 · ch-local fetch] ch-file://….png` line) makes Claude read the clipboard first (`xclip … || wl-paste`); meanwhile it shows `Pasting…` under an empty box and drops any Enter. The text lands afterwards, unsent, and sat there; the next message was then refused for that draft. Claude checks every line of a paste (split at LF) that ends in a picture name, so the ch picture lines now carry a note after the address (see Pictures), which Claude takes in one go (checked live). Herdr's `agent prompt` and the relay path both pressed Enter ~0.15 s after the paste.
- **Before the receipt** (read-only): a dialog with no box refuses (`没发出去：它正停在一个提问或选择框上…`); `Pasting…` still shown after 3 s refuses (`没发出去：它还在处理上一次粘贴…`, the queue retries it by itself).
- **Clearing** (after the receipt): rounds of `ctrl+e ctrl+u ctrl+k backspace` (end of line, delete to the line start, on the now empty line delete the line break after it, then the one before it), one round per box line plus one (≤ 40), up to 3 times, each followed by screen reads until the box reads empty. Chips (`[Pasted text #1 +30 lines]`, `[Image #1]`) go with their line. Checked live on Claude Code 2.1.268 and Codex 0.163 (multi-line, cursor mid-text, chips; an empty box ignores all four keys). Never Esc (Claude: twice on an empty box opens rewind; Codex: arms "edit previous message"; both interrupt a turn), Ctrl+C (interrupts, or exits from an empty box), Ctrl+D (exit), Up/Down (history) or Delete (not a Herdr key). A box that does not read empty refuses: `没发出去：它输入框里原来的字没能清干净…`.
- **Paste**: the message (CRLF as LF, ESC removed so it cannot end the paste early) as one bracketed paste, no Enter. Enter only after two reads in a row show the box holding it: the same characters once whitespace is ignored, or, where the agent drew chips, every other character it shows in order within the message (Claude moves a local picture's chip to the front and drops its path). Up to 8 s; `Pasting…` keeps it waiting. Otherwise nothing is pressed and the prompt is not sent: `…一直显示「Pasting…」…` (`late`), `…一直没出现这条…` (`missing`), `…对不上…` (`other`), `…输入框不见了…` (`gone`).
- **After Enter**: reads for up to 5 s. An empty box is `verified: true`. A box still showing exactly what it showed before Enter for 3 reads means Enter was dropped (submitting empties the box): Enter once more (`retried: true`), never a second paste; still there after that is `没发出去：字进了它的输入框，可按了两次回车都没发出去…` (`enter`). Anything else (unreadable, no box, other text) is `verified: false`: it may well have gone and is never resent.
- **Result**: `{sent: true, receipt, verified, replaced[, retried]}`; `replaced` when old text was cleared. The not-sent cases above are stored as `{sent: false, rejected: <code>}` under the request id and start with `没发出去`. A screen read that fails after the paste falls back to the old Enter after 0.3 s (`verified: false`). A write failing before the first Enter is not sent (the paste is bracketed, its line breaks stay text); one failing at or after Enter leaves the receipt unknown, as before.
- `exitAgent` with text in the box clears it the same way first (or refuses as above), then sends `/exit` / `/quit` as before.
- The phone shows a quiet note: 「覆盖了它输入框里原来的字」, 「屏幕上没确认到它收下了，留意一下」.

## What the agent is doing (protocol remains v1)

- `read` (Herdr and tmux agents) adds `activity` when the agent's own live status line is on screen: `{verb, seconds?, tokens?, dir?, thinking?, line}` (Claude Code "✽ Ionizing… (42s · ↓ 1.2k tokens · esc to interrupt)", Codex "• Working (1m 02s • esc to interrupt)"). For Claude only the line right above its input box counts (past its todo list), elsewhere the bottom lines; a finished line ("✻ Crunched for 7s") or a bullet in the conversation is not activity. It is parsed from the same screen read, never decides the agent's state, and is absent when there is no such line.
- Sub-agent reports (`kids` in `glance` / `history`, also from a ch route's remote helper) add, for the newest `KIDS_LIVE` (4) running sub-agents only, `activity` (the glance shape: `{kind: tool|note|agent, verb, text, open, at}` from the child's own last 64 KB), `started` (its current task's timestamp), `tools` and `failed` counts. Finished sub-agents are not read. `waiting: true` means a running sub-agent is waited on by Claude itself: the parent transcript's newest own row is a `Agent` / `Task` tool_use whose result has not been written (queue/notification rows in between do not count as a resume). The phone treats that parent as held by its sub-agents and sends new messages straight in; a background launch writes its `Async agent launched` result at once, so it is not `waiting`.
- The phone shows these in the conversation's activity line (已发出，等它开始… / 正在执行 / 正在思考 / 正在输出 / 子 Agent 在跑 / 状态有一会儿没更新了 / 状态未知); it is read-only and sends nothing.

## /status and /usage: Claude's settings panel (protocol remains v1)

- Claude Code 2.1.268 draws /status, /usage, /config and /stats as one full-screen panel with tabs (`Settings  Status   Config   Usage   Stats`); each command opens it on its own tab and the screen shows only that one. Seen live (Herdr 0.8.2 and tmux, 100×40 / 90×20 / 80×18 panes, with and without `NO_COLOR`): ←/→/Tab switch tabs and wrap round; Status (and Usage) scroll one row per ↓ / ↑ in a short pane, with ↑ / ↓ marks at the right edge and the "Esc to cancel" footer only once at the bottom; a tab switch starts the next tab at its top; Esc closes the panel and leaves nothing of it on screen or in scrollback; Herdr keeps calling the agent `idle` while it is up. Config reached with → keeps its focus on the tab row ("←/→/tab to switch · ↓ to return · Esc to close"); ↓ there enters its search box and then the settings list, where Enter/Space change a setting. /config itself opens with the search box focused (Esc only clears it). Stats takes ↓ into its own view. The tab in front differs only by colour, so tabs are recognised by content (Status: `Version:` / `Session ID:` / `cwd:` …, Config: the "Search settings" box, Usage: `Total cost:` / "Current session" / `N% used`, Stats: its "Overview  Models" row).
- `panelTour` (mutation; `session`, `target`, `identity`, `id` UUID, `command`: `"status"` or `"usage"`, nothing else) walks that panel and closes it. Refused before any key (`没按键：…`) unless the agent is Claude, Herdr says `idle`/`done` (tmux: its screen is not working), the visible screen shows the panel, no dialog parses there, the focus is on the tab row (no "Type to filter", "Enter/Space to change", "/ to search", "Enter to …" hint) and the tab in front is recognised. Then the receipt is written and only these keys are pressed, each followed by re-reads of the visible screen until it settles (same rows twice, nothing "Loading"): → once per remaining tab, accepted only when the next tab shows up by content (or, unrecognised, the tab row is still there and the rows changed); ↓ to bring in Status / Usage rows below the screen until the footer shows (at most 40), and ↑ first when such a tab was found scrolled part-way (↑ on its top row); Esc at the end. Any surprise stops the walk; Esc is then sent only while the screen still shows the panel (Esc on this panel cancels and never changes a setting), never to a screen without it. Config is never scrolled (its rows past the screen are reported, not read) and Stats never gets ↓. The whole walk stops after about 22 s.
- Result: `tabs` (`[{tab, text, more}]` in the panel's own order; `text` is the rows between the tab row and the footer with the edge marks removed, scrolled rows merged; `more`: rows remain off screen, or Config's "↓ N more below"), `order`, `start`, `closed` (the panel is gone from the screen), `steps` (the keys pressed), `stopped` (why it stopped early, if it did), `sent`, `receipt`. As with every mutation the same id answers from its receipt and an unknown outcome (a key may have gone in) is never replayed.
- The phone calls it only right after the person's own `/status` or `/usage` went out from the phone (typed or picked from the list, also from the queue), once, when the command card's first read finds the panel with Claude idle and no picker. It never calls it for /config, a command with arguments, a panel the person opened on the computer, or a card's later refresh. The card shows every tab as rows ("Key: value" with wrapped values joined, two-column settings, usage bars with their reset time, headings), the terminal text behind 「终端原文」, and one 「复制」 for all tabs. Codex /status is one screen: the card shows its rows (between the echoed `/status` and the composer) without pressing anything.

## CC Switch: providers and model switching (protocol remains v1)

The desktop CC Switch app (v3.20.2) stores providers in `~/.cc-switch/cc-switch.db` (SQLite: `providers`, `settings`) and the selected ids in `~/.cc-switch/settings.json`. That desktop build has no reliable CLI while its GUI runs (`--help`, `provider list` and `provider current` print nothing), so these ops use a guarded direct-config path in the bridge. No shell is involved; target paths are fixed under the SSH user's `$HOME`.

- `ccswitch` (alias `providers`) — read-only, no fields. Opens the DB as `file:…?mode=ro` with a timeout and reads only `providers` and the two `common_config_*` settings rows. Returns:

  ```json
  {
    "available": true,
    "apps": ["claude", "codex"],
    "current": {"claude": "<provider id or null>", "codex": "<provider id or null>"},
    "providers": [{
      "id": "<id>", "app_type": "claude|codex", "name": "<name>",
      "is_current": true, "official": false, "switchable": true,
      "models": [{"slot": "默认", "model": "<model>", "name": "<display name, optional>"}],
      "model_provider": "<Codex model_provider, optional>",
      "reason": "<why it cannot be switched, optional>"
    }],
    "note": "密钥只留在电脑上。"
  }
  ```

  Claude model slots come only from `settings_config.env`: `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_FABLE_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`, plus the matching `*_MODEL_NAME`. Codex returns only `config`'s `model` and `model_provider`. **Tokens, API keys, base URLs, `settings_config` and arbitrary file paths are never returned.** Official rows (`claude-official`, `codex-official`, `default`) and providers with no writable config are listed with `switchable: false` and a human reason. A missing or unreadable CC Switch answers `{"available": false, "reason": "电脑上没有 CC Switch" | "CC Switch 的数据库读不出来（可能版本不兼容）", "providers": []}` rather than an error.

- `ccswitchSwitch {app, provider}` — `app` must be `claude` or `codex`; `provider` must be an id present in the DB for that app (it is never a path or free-form config). Official/no-config providers are refused before anything is written. The bridge:
  - **Claude**: merges `settings` → `common_config_claude` (env defaults, hooks, model, …) with the provider's `settings_config` and writes `~/.claude/settings.json`. The `env` object is replaced (another provider's token/model slots never survive); the current `statusLine` and user tables such as `modelSettings` are kept; hooks are unioned.
  - **Codex**: merges `common_config_codex` (projects/trust) and the provider's `config` TOML over `~/.codex/config.toml`. User `projects`/trust, `tui`, `plugins`, `mcp_servers`, hooks and other tables are kept; provider-managed top-level keys (`model`, `model_provider`, `model_reasoning_effort`, `disable_response_storage`, `model_providers`) replace stale values. The provider's `auth` is written to `~/.codex/auth.json` when present (an `env_key` provider keeps the current auth file).
  - Every replaced file is copied first to `<file>.ccswitch-backup-<YYYYmmdd_HHMMSS>` (0600, collision-suffixed). New files are written to a temp file in the same folder, `fsync`ed, atomically replaced and chmodded 0600. `~/.cc-switch/settings.json` gets `currentProviderClaude`/`currentProviderCodex`; `providers.is_current` is updated in one SQLite transaction (a locked GUI DB yields a warning, not a config rollback).
  - Result: `{"switched": true, "app", "provider", "name", "new_sessions_only": true, "backup_count", "message", "warning"?}`. No secret or filesystem path is included. Only new sessions read the new config; a running Agent is never restarted or messaged. Model slots of the *current* provider can still be changed inside a running Claude session with `/model <slot>`.

## 文件: SFTP browsing and transfers (native, not bridge ops)

These requests never reach the bridge; they run on an SFTP channel of the named computer's own SSH session (`device` is required by the page for each of them), with that SSH user's permissions. A channel that fails to open is "not sent" and retried once after a reconnect, like a bridge request; nothing else is retried.

- `sftpList {device, path}`: `path` is absolute, `~` or `~/…` (normalized on the text, then `realpath`). Returns `{path, home, parent, entries: [{name, type: dir|file|link|other, size, mtime, perm, target?}], truncated, downloads}`; at most 3000 entries; a link gets `target` (`dir`, `file`, `broken`, …) from one `stat`. `downloads` is false below Android 10 (only 另存为 then).
- `sftpMkdir {device, dir, name}`, `sftpRename {device, path, name}` (same folder, never onto an existing name), `sftpDelete {device, path, recursive?, confirm?}`: refusals carry `code` (`sftp_exists`, `sftp_not_empty`, `sftp_confirm`, `sftp_missing`, `sftp_denied`, `sftp_too_many`, `sftp_partial`, `sftp_name`, …). `recursive` requires `confirm` equal to the folder's name.
- `sftpPickUpload {}` opens the system document picker (several files, ≤ 50); returns `{files: [{id, name, size}], failed, reason, extra, cancelled}`. `sftpDropPicks {ids}` forgets picks that will not be uploaded.
- `sftpUpload {device, dir, id, name, mode: new|keep|replace}` and `sftpDownload {device, path, size, saveAs?}` start a transfer and return it at once; `saveAs` first opens the system "create document" screen (`{cancelled: true}` when backed out). A transfer is `{id, device, deviceName, kind: up|down, name, remote, size, done, state: queued|running|done|failed|cancelled, phase: copy|verify, error, where, saved, canOpen}`. `phase` is `verify` while a running transfer checks the size and moves the finished temporary file into place; the page shows it as 正在核对… and never advances the bar past the last `done` native reported.
- `sftpTransfers {}` lists the last 40 (all computers); `sftpCancel {transfer}`; `sftpForget {}` clears finished rows; `sftpOpen {transfer, share?}` opens or shares a finished download (`ACTION_VIEW` / `ACTION_SEND` chooser) by its id.
- `sftpPreview {device, path, kind: text|image|pdf, tail?, allowLarge?, width?, token?}` reads one regular file into the app's own cache and returns `{key, name, mime, size, mtime, cached, complete, path}` plus one of: text `{text, encoding, binary, shown, truncated, tail, offset}`; image `{url, width, height, origWidth, origHeight, derived?, note?}`; pdf `{page: {url, width, height, index, pages, note?}, sizes?: [[w, h], …]}` (`sizes` is every page's size in PDF points so the continuous view can lay out all pages before they render; omitted above 2000 pages). Text is decoded natively (UTF-8, else GB18030) and capped at 5 MB from the start, or the last 512 KB with `tail`; a NUL-heavy file is reported `binary` and no bytes are sent. Images and PDFs above 20 MB need `allowLarge` (nothing above 300 MB). Progress is pushed as byte counts through the normal request progress channel. `token` lets `sftpPreviewCancel {token}` stop a read at its next block.
- Image `url` is `https://pocket.invalid/preview/<40-hex-key>`; PDF page `url` is `https://pocket.invalid/preview/page/<40-hex-token>`. No image or PDF page is sent as `data:`. A complete JPEG/PNG/GIF/WebP/BMP/AVIF original up to ~36 MB and 14 MP is served as the cached source file itself (no re-encode; animated GIFs keep moving). Anything larger, or a format the WebView may not decode (e.g. HEIC), is decoded natively with full EXIF orientation (including flips/transpose), fitted to a 4096 px long edge and a 12 MP cap (3072 px / 6 MP on low-memory devices), and encoded as JPEG 92 (PNG when it has alpha) into a derived cache entry. An over-limit GIF falls back to its first frame and sets `note`.
- PDF pages are rasterised one at a time under one native lock. `width` is clamped to 240–4096; the total page bitmap stays at or below 10 MP (6 MP on low-memory devices), JPEG quality 92. A page file is keyed by SHA-1(source key + page + rendered width + renderer version), so re-opening the same page/width reuses it. An out-of-memory render is retried once at half width. Derived pages are served as `image/jpeg` through the page URL. The UI shows all pages in one vertical scroll and asks `sftpPreviewPage {key, page, width}` only for pages near the screen: fit-width pages at the device pixel density (1200–3000 px), and a 2.5× render for the pages on screen once zoomed past 140%.
- `sftpPreviewPage {key, page, width?}` renders another page of a PDF already fetched; `sftpPreviewOpen {key, share?}` opens or shares a complete cached preview through the non-exported `PreviewFiles` provider by its key (never a URI from the page). Preview sources live in `cacheDir/sftp-preview/` (250 MB cap); image, PDF-page and Office-image derivatives live separately in `cacheDir/sftp-preview-derived/` (120 MB cap). `cacheClear` removes both. Source entries are authorized by their in-memory preview metadata and derived pages by a separate registry. A page request never prunes the source PDF it is reading.

### Local preview asset channel (`https://pocket.invalid`)

The bundled page loads images/PDF pages only through the WebView's `shouldInterceptRequest`, never from the network. `https://pocket.invalid/preview/<key>` serves source/rendered images and complete PDF sources; `/preview/page/<token>` serves one rendered PDF page; `/preview/office/<token>` serves images extracted from Office documents (registered derived assets). The route accepts only `GET` and `HEAD` (405 otherwise), validates `https`, host `pocket.invalid`, an exact `[0-9a-f]{40}` token and a currently registered, completed asset (404 for unknown, unregistered or evicted; 403 for another origin). The MIME allowlist is JPEG/PNG/WebP/GIF/BMP/AVIF plus `application/pdf`; `text/html`, `image/svg+xml` and script MIME types are refused. Responses carry `Content-Type`, `Content-Length`, `Accept-Ranges: bytes`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff` and `Content-Disposition: inline`. A single `Range: bytes=start-end|start-|-suffix` returns 206 with `Content-Range`; malformed or unsatisfiable ranges (including multiple ranges) return 416 with `Content-Range: bytes */<size>`. Files are opened with `FileInputStream` and streamed through a byte limit; the page never supplies a filesystem path. The page CSP is `default-src 'none'` with `img-src data: https://pocket.invalid`, `object-src 'none'`, `worker-src 'none'` and no `media-src`.

- `sftpMediaOpen {device, path, allowLarge?, token?}` caches one complete video/audio file over SFTP into a separate `cacheDir/media-preview` (own 1 GB LRU quota) and returns `{key, name, mime, size, mtime, cached, complete, path, media: {kind: video|audio, durationMs?, width?, height?, rotation?, title?, artist?, album?, container?}, poster?}`. Files above 20 MB need `allowLarge`; nothing above 1 GB is cached. Free space is checked first; the byte count must equal the SFTP size before the temporary file is renamed into place. Progress is pushed as real byte counts through the normal request progress channel; `sftpMediaCancel {token}` stops a read at its next block. `poster` is a `data:image/jpeg;base64,…` (≤ 512 px) from embedded artwork or the first video frame. No media bytes or media URL ever reach the page.
- `sftpMediaPlay {key}` starts the non-exported native `PlayerActivity` (`TextureView` + `MediaPlayer`) for a complete cached file; `sftpMediaExternal {key, share?}` opens or shares it (`ACTION_VIEW` / `ACTION_SEND`) through `PreviewFiles`. The file is pinned while the player is open, so prune and `cacheClear` cannot delete it; the pin ends in `PlayerActivity.onDestroy`. A JSON sidecar next to the file keeps the original name/MIME/metadata across process death, and the file name keeps its original extension as a second fallback. Playback is local-only: no streaming, background audio, PiP or subtitles.

## 文件: Office reading view (native, not bridge ops)

`.docx`, `.xlsx` and `.pptx` are parsed on the phone from a complete private-cache copy (the same SFTP read as `sftpPreview`, `kind="raw"`). Parsers are pure Kotlin (`java.util.zip` + a pull parser); no macros, scripts, external relationships or remote resources are loaded, and responses contain structured text/numbers only — never XML or HTML. At most four sessions are kept, least recently used first.

- `sftpOfficeOpen {device, path, token?, allowLarge?}` reads the complete regular file and returns `{session (16 hex), kind: docx|xlsx|pptx, name, mime, size, mtime, key}` plus the first content: DOCX `{blocks, from, next, total, done, truncated, chars}`, XLSX `{sheets: [{index, name, hidden}], styles, sheet: rowWindow}`, PPTX `{slides, width, height, slide}`. Progress uses the normal byte-count progress channel; `token` lets `sftpOfficeCancel {token}` stop the read. Above 20 MB `allowLarge` is required; above 80 MB the document is refused. Legacy `.doc/.xls/.ppt`, macro-enabled/ODF/RTF, encrypted entries, OLE compound files and damaged archives return a readable `office_legacy` / `office_encrypted` / `office_unsupported` / `office_damaged` code for the download/open fallback.
- `sftpOfficeChunk {session, from?, count?}` returns the next DOCX block window `{from, next, total, done, truncated, blocks}`. Blocks are `{t:"p",p}` (runs with `b/i/u/s/color/sz/link`, `h` heading 1–6, `al`, `lvl`, `marker`, `ord`, indents), `{t:"table",rows}` (cells with `cs` gridSpan, `rs` rowSpan, `cover` for vMerge continuations, `fill`, nested blocks), `{t:"img",asset,w,h}` and `{t:"br"}` (page break). Responses are capped at roughly 360 KB even when a table is large.
- `sftpOfficeSheet {session, sheet, start?, count?}` returns a row window `{sheet, name, start, count, totalRows, cols, widths, merges: [{r1,c1,r2,c2}], rows: [{i,h,hidden,cells: [{c,v,t,s}]}], truncated}`. `styles` (from open) are `{b,i,u,s,color,fill,al,val,wrap,format,date,sz}`. Formulas are never evaluated: the cached `<v>` result is shown. Cells cap at 20 000 rows / 200 000 cells / 4 M characters per sheet; the page virtualises rows and requests 200-row buckets.
- `sftpOfficeSlide {session, index}` returns one slide `{index,w,h,bg,bgAsset?,title?,truncated?,shapes}`. Shapes are `{k: text|image|placeholder|table, x,y,w,h (EMU), fill?, name?, label?, asset?, ps}` with DrawingML runs/paragraphs. Charts, SmartArt and embedded objects become placeholders. Slide order and size come from `presentation.xml`; backgrounds fall back to the slide layout.
- `sftpOfficeClose {session}` drops the session and its ZIP handle. `sftpOfficeCancel {token}` cancels a running acquisition.
- Office images are extracted natively, bounded per image (16 MB, PNG/JPEG/GIF/WebP/BMP only) and registered as 40-hex derived assets (`Previews.putDerived`, `AssetKind.OFFICE`, derived cache). The page requests them from the Phase 1 asset channel as `https://pocket.invalid/preview/office/<key>`; `PreviewServer` authorizes the token through the same derived registry as PDF pages. Office documents themselves stay in the private preview cache and can be opened/shared through `sftpPreviewOpen {key}`.
## Herdr server: health, 启动 Herdr and 守护 (protocol remains v1)

- `doctor` adds `server: {state: running|mismatch|stopped, version}` for the default session (from `herdr status server --json`). `sessions` adds `server: {pid, started, clean}` (the run that is up, from `herdr-server.log`, no subprocess) while the default session runs, so the phone can tell that Herdr restarted.
- `herdrHealth {}` (read-only) → `{installed, platform, client: {version, protocol}, server, start?, guard}`. `server.state`: `running`, `mismatch` (running but `compatible: false`), `busy` (not answering while a process still holds its socket), `stopped`, `error`; plus `version`, `protocol`, `compatible`, `restart_needed`. Running: `pid`, `started` and `previous` (how the run before ended). Stopped: `ended`. An end is `{pid, started, at, how: clean|crash|oom, oom?: kernel|earlyoom|systemd-oomd, line?, boot?: true (the computer restarted since), journal?: false (the journal could not be read)}`; `crash` = no `app.shutdown` logged for that pid (SIGKILL, a crash); SIGTERM/SIGHUP/SIGINT and `herdr server stop` all log a clean shutdown (checked with Herdr 0.8.2). `start` (stopped only): `{method: systemd|detached, linger, kill_user_processes}`. `guard`: `{supported, kind: systemd|cron|null, reason?, installed, active?, enabled?, boot?, always?, outdated?, events?: [{at, what: started|left|failed|already|error, reason: crash|oom|unknown|stopped|before|missing, method?, oom?}], foreign?: <unit path that is not ours>}`.
- `herdrStart {id}`: refused before the receipt (`没启动：…`) when Herdr runs or its socket is held; a reused id returns the stored result. Then `herdr server` as `systemd-run --user --unit=herdr-pocket-server --collect -p WorkingDirectory=~ [-p OOMScoreAdjust=<floor>] --setenv=PATH=… -- <herdr> server` when lingering, else detached in a new session; waits up to 8 s for `status` to say running. Result `{started, already, running, method, unit?}`; a failed start is stored as `{failed}` and reported `没启动：…`.
- `guardPlan {boot?: true, always?: false}` (read-only) → `{supported, kind, reason?, options, files: [{path, content, sha256?, what}], cron?: [lines], commands, remove, digest, herdr, oom?: {floor, default, set}, linger?}`. `digest` = SHA-256 of kind, file paths and contents and cron lines.
- `guardSet {id, enable: true, boot, always, digest}` installs exactly that plan (refused with `没开：…` before the receipt when the digest differs or the computer is unsupported; a unit file not written by Herdr Pocket is never replaced) → `{enabled, kind, active, status}`. `guardSet {id, enable: false}` removes it → `{enabled: false, removed: [paths]}`. Both use the normal receipts; failures after the receipt are stored as `{failed}`.
- The guard script (`herdr-guard.py --watch|--once [--boot] [--always] [--herdr PATH]`) is embedded in the bridge (`GUARD_SCRIPT`) and loaded by it, so the bridge and the guard decide and start the same way. See SECURITY.md "Starting Herdr and the Herdr guard".
- Phone: a stopped Herdr shows a card on 会话 (how it ended, the agents of the last list that went with it, 「启动 Herdr」, 「开启 Herdr 守护」, 去历史) and a banner elsewhere; the 设备 card has Herdr and Herdr 守护 rows. After a restart (a newer `sessions.server.started` than the last list kept in the encrypted cache under `herdr`: titles, kinds and agent session ids) 会话 shows once which agents came back (same `agent_session` value: Herdr's `resume_agents_on_restore` reopened them) and which did not; 「去历史找回对话」 calls `resumeLost(list)` when another module defines it, else opens 历史.
